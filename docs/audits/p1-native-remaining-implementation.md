## Recommended immediate implementation envelope

Start with **Crew work detail and outbox**, owning new native screens/view-models and the narrow vault query surface. Keep backend authorization, authentication and event semantics unchanged. The read-only outbox and durable checklist projection are accepted. Sequential photo reads are also accepted. Continue with saved-entry detail, per-item sync outcomes and approved conflict escalation. A server resolution API, if needed, must be separately designed/reviewed rather than hidden in a UI patch.

Acceptance: download two assigned jobs; save notes/checklist/time/photo offline; leave/reopen and restart; see exact local work; sync accepted items; inspect a deliberate conflict; retry a lost acknowledgment without duplication; prove unrelated accepted work can progress around a target-specific failed photo; retain all unresolved evidence through role denial and same-account recovery. Include101+ operations and memory-bounded photo processing. This closes concrete first-envelope shortcomings while the author continues independent device testing.

## Broader native roadmap remains open

The first envelope deliberately leaves office approvals, commercial editing and billing decisions on the web. That limit is not permanent product scope. Preserve the master property domain: assessments/inspections/issues, maps/areas/assets, recurring services, projects/prerequisites, scheduling/crew availability, reporting and property health, portfolio views and future fleet/equipment. The commit has no native screens for most of these. Sequence expanded native workflows from accepted shared backend contracts and role needs; the master does not require every office mutation to be duplicated blindly on mobile. `docs/dashboard/README.md:19–27` also records unfinished shared operational/reporting requirements; native UI cannot substitute for those backend/web contracts.

Next after crew usability: role-specific client/staff navigation and complete existing read contracts; then approved assessment/inspection/report and property-context slices alongside their shared operational owners. Keep common canonical identity and explicit publication throughout. No duplicate backend, local authorization grants or relaxation of MFA is proposed.

## Validation and limits

This audit inspected committed app/screen/storage/sync/capture/config files, native file inventory, master plan, accepted native proposal and dashboard scope. Source parity was checked for the six cited implementation files. The original audit itself executed no runtime tests. Subsequent accepted work includes actual Android outbox/expiry checks, SQLite pagination and isolation, before/after actual App sync-sequence reproduction, 48 passing native tests, parameterized single-photo SQLite read checks, typecheck and both Hermes exports. Timeout regressions cover delayed headers/body, native abort signals, late responses, account changes, listener/timer cleanup and same-ID retry after a simulated lost receipt. A bundled Android emulator fixture using Expo native fetch and the real BusinessTransport observed server connections close before completion for delayed headers, delayed body and photo upload. Its disposable loopback adapter and test-only cleartext allowance establish cancellation behavior, not release TLS or physical-device acceptance. The ID snapshot still scales with queue size; physical heap, garbage collection and OS upload buffers have not been measured. This evidence applies only to the described implemented slices. Device gates remain: actual iOS build, physical iPhone/Android, real auth plus native transport, process-kill/reboot, camera/low-space/backup/key-loss, accessibility and controlled pilot. Signing/distribution and production authorization remain separate. This document update changes no code, authentication, schema, provider or deployment.
