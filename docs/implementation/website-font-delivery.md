# Website typography migration and delivery

The original 20 options, labels, families, classifications and preview descriptions now live in Core's shared `website-fonts.ts`. The retained admin client imports that catalog; the consolidated API uses it to validate font identifiers. A source comparison verifies all 20 entries remained unchanged. This avoids a competing font catalog.

Marketing → Design → Typography is gated by `marketing.design.typography`. Body and heading selections save only changed fields with the existing branding category version and an atomic key-list audit. Unknown saved selections remain visible and are not overwritten by changing the other field. Clearing a selection means website theme default. Legacy generic mutations are intentionally redirected with 409 to close the broader legacy permission path; release Core and dashboard together. No database migration is needed.

Core publishes only known name/fallback pairs, never raw font strings, metadata or unrelated branding. The public gateway rejects unknown payload shape/identity, unsafe family syntax, nonstandard fallback categories, redirects, malformed UTF-8 and bodies over 16 KiB. Refreshes have a 1.8-second timeout, coalesce and cache for 30 seconds. Failed refreshes drop expired overrides; clearing both fonts emits no typography markup. No disk fallback or visitor credential forwarding is used.

The gateway sets the existing `--app-font-sans`, `--app-font-serif` and `--app-font-display` variables. It requests unique selected families from the fixed Google Fonts CSS endpoint, with regular/bold weights and `display=swap`, under the website's existing CSP. It does not add Google Fonts access to the Business Center CSP. Actual font downloads remain subject to provider/browser availability and normal fallback behavior. Page-specific font overrides still take precedence. Global settings refresh on a full document load after cache expiry, not automatically in already-open pages.

Public HTML and CMS previews receive saved font settings. Proxied admin/API responses and static assets do not. The Typography screen links to the saved public preview. An unsaved in-dashboard font specimen comparable to the old admin remains a Design parity item; it must not silently rely on remote font styles blocked by dashboard CSP.

Deploy Core's projection and the gateway consumer with the editor before claiming public delivery. Review actual saved selections, font downloads, layout shifts, responsive line wrapping and accessibility before production activation. Local browser evidence uses blocked external networking and establishes CSS declarations and scope, not vendor font-file availability. Rollback the gateway consumer to retain built-in fonts without deleting saved settings. No production settings or deployments were changed during this implementation.
